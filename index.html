YOUR PRACTICE ROUTINE

Build a workflow you can trust.

These are suggested developer exercises, not model benchmarks. Use the same repository and acceptance criteria when comparing models.

  1. Give it a real brief. Describe the user problem, relevant paths, stack, constraints, and the result you will accept. Include a reproduction or screenshot when it clarifies the behavior.
  2. Choose a mode of work. Say whether you want an explanation, an implementation, or a review. Supply the repository for edits, a runnable environment for execution, and the relevant sources for research.
  3. Steer with specifics. If the result misses the mark, point to the exact behavior, file, screenshot region, or failed command. Give one actionable correction and keep the original goal visible.
  4. Measure your own result. Compare a feature, a reproduced bug, and a code review. Track accepted quality, elapsed time, cost, retries, and human intervention. Change effort only when the result warrants it.
  5. Save what worked. Turn a successful prompt into a small reusable template. Record stable project conventions in AGENTS.md or CLAUDE.md and revisit them when models or tools change.

A model choice does not supply tools by itself. In a text-only chat, request an explanation or patch you can apply; in Work, Codex, or Claude Code, make the needed files and execution tools available. Review the actual diff and evidence before release.
